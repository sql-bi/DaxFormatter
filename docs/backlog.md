## Known debt
- The clients send enums in different forms: the .NET client sends `ServerMode`, `ServerEdition` and `ServerLocation` as numbers, the TypeScript port as strings; `ServerType` is a string in both. Cost: the service receives two forms of the same fields, a new client has no rule to follow, and changing the .NET form changes the wire format of a published package. Repay with the OpenAPI contract, which fixes one form for every client.
- The REST contract is restated in each client: the .NET request and response models, the TypeScript port's types and serializer, and the zod schemas of the MCP tool. Cost: every contract change touches each copy, and the copies already drift (the enums above). Repay with the OpenAPI contract and its shared test vectors.
- The getting-started sample references `Dax.Formatter` 1.0.0, while nuget.org has 1.2.2. Cost: the sample builds against a package from 2021, not the one users install. Repay in the next change to the sample.
- The .NET tests call the live service (`DaxFormatterClientTests`). Cost: .NET CI depends on the service and the network, and an outage fails unrelated pull requests. Repay with the shared test vectors: unit tests against recorded responses, and the live tests in a separate job.
- The MCP server says that `formatted` is null for invalid DAX, in the tool description in `typescript/packages/daxformatter-mcp/src/format-tool.ts` and in the comment of `formatted` in `src/daxformatter/types.ts`, while the service returns an empty string ([REST API, Response](design/rest-api.md#response)). Cost: an AI client that follows the tool description misses the empty string. Repay by fixing both texts, which raises the MCP server's version.
- Releases are tied to `master` only by the branch guard of the release workflows: a run uses the workflow file of the commit it runs on ([Workflows](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows)), so a branch whose copy drops the guard runs with the repository secrets, and the nuget.org Trusted Publishing policy names the workflow file, not a branch. Cost: whoever can push a branch and run workflows can publish from it. Repay: remove the nuget.org policy for `release.yml`, the .NET release workflow's name before the move in `6df1bf0`; run each release job in a GitHub environment that only `master` can deploy to, which holds the release secrets and which the nuget.org policy names ([Trusted Publishing](https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing), [environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments)).
- Some files under `dotnet/` don't follow `.editorconfig`: a missing or unwanted byte order mark, no final newline, trailing whitespace, and tabs, including in the two `.sln` files, which Visual Studio writes with tabs. Cost: saving one in an editor that applies `.editorconfig` puts changes unrelated to the edit in the diff. Repay with one commit that only normalizes these files, and a `[*.sln]` section with `indent_style = tab`.
