## Known debt
- Enum wire format diverges between the clients: the .NET client sends `ServerMode`, `ServerEdition` and `ServerLocation` as numbers (System.Text.Json web defaults, no converter), while the TypeScript port sends them as strings; `ServerType` is a string in both (`EnumMember` values through `JsonEnumMemberConverter` in .NET). Cost: the service receives two forms of the same fields, and a new client has no rule to follow; changing the .NET form changes the wire format of a published package. Repay with the OpenAPI contract, which fixes one form for every client.
- The REST contract is restated in each client: the .NET request and response models, the TypeScript port's types and serializer, and the zod schemas of the MCP tool for the options it exposes. Cost: every contract change touches each copy, and the copies already drift (the enum wire format above). Repay with the OpenAPI contract and its shared test vectors.
- The getting-started sample references `Dax.Formatter` 1.0.0, while nuget.org has 1.2.2. Cost: the sample builds against a package from 2021, not the one users install today. Repay in the next change to the sample.
- The .NET tests call the live service: `DaxFormatterClientTests` uses a real `DaxFormatterClient`, so .NET CI depends on the service and the network, and an outage fails unrelated pull requests. The MCP tests inject a mock `fetch` and run offline. Repay with the shared test vectors: unit tests against recorded responses, and the live tests in a separate job.
- The MCP server says that `formatted` is null for invalid DAX: the tool description in `typescript/packages/daxformatter-mcp/src/format-tool.ts` ("Invalid DAX: `formatted` is null") and the comment of `formatted` in `src/daxformatter/types.ts`, while the service returns an empty string ([REST API, Response](design/rest-api.md#response)). Cost: an AI client that follows the tool description checks for null and misses the empty string. Repay with a change to the tool description and the type comment, outside the language-first layout plan, which raises the MCP server's version.
- Releases are tied to `master` only by the branch guard of the release workflows: a run uses the workflow file of the commit it runs on ([Workflows](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows)), so a branch whose copy of a release workflow drops the guard runs with the repository secrets, and the nuget.org Trusted Publishing policy names the workflow file, not a branch. Cost: whoever can push a branch and run workflows can publish from it. Repay: remove the nuget.org policy for `release.yml`, the .NET release workflow before the [move](../CONTRIBUTING.md#reading-history-across-the-move), which no workflow on `master` uses any more; run each release job in a GitHub environment that only `master` can deploy to, with the release secrets moved into it and the environment named in the nuget.org policy ([Trusted Publishing](https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing), [environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments)).
- Some files under `dotnet/` don't follow `.editorconfig`. Byte order mark: `src/Dax.Formatter/AssemblyInfo.cs`, `src/Dax.Formatter/Client/Http/DaxFormatterHttpClient.cs` and `tests/Dax.Formatter.Tests/DaxFormatterClientTests.cs` lack the one it asks for in `*.cs`; `samples/GettingStarted/BasicFormatter.csproj` and `tests/Dax.Formatter.Tests/Dax.Formatter.Tests.csproj` have one, which it rules out in project files. Final newline: `global.json`, `nuget.config`, `BasicFormatter.csproj`, `src/Dax.Formatter/IDaxFormatterClient.cs` and `src/Dax.Formatter/Client/Http/IDaxFormatterHttpClient.cs` have none. Trailing whitespace: `README.md`, `BasicFormatter.csproj`, `samples/GettingStarted/Program.cs`, and `Models/DaxFormatterRequest.cs`, `Models/DaxFormatterMultipleRequest.cs`, `Security/SecurityHelpers.cs` and `Serialization/JsonEnumMemberConverter.cs` under `src/Dax.Formatter/`. Tabs: `src/Dax.Formatter/AnalysisServices/ServerLocation.cs` and `ServerMode.cs`, and the two `.sln` files, which Visual Studio writes with tabs while `[*]` asks for spaces. Cost: saving one in an editor that applies `.editorconfig` changes its byte order mark or whitespace, so the diff shows changes unrelated to the edit. Repay with one commit that only normalizes these files, and a `[*.sln]` section with `indent_style = tab`.
